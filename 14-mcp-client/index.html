An MCP client in the browser

The page is the MCP client: it runs the JSON-RPC handshake (initialize → tools/list) against an MCP server over Streamable HTTP, then hands the discovered tools to Chrome's built-in LanguageModel (Gemini Nano), which drives them through a responseConstraint intent loop. Lesson: An MCP client in the browser.

Checking availability…

1 · Connect to an MCP server

The default mock server answers initialize, tools/list and tools/call in-page, so the whole loop runs offline with no network and no CORS. Switch to a remote URL to speak to a real server.

Browser → remote MCP is CORS-gated: the server must send Access-Control-Allow-Origin for this origin and expose Mcp-Session-Id. If it doesn't, run a CORS proxy and put its address in the prefix (or in the URL). The bearer token is kept in memory only — never stored, never logged.

2 · Ask the on-device agent

Gemini Nano runs the intent loop: it emits one JSON tool call per turn, the page dispatches it to the server as tools/call, the result feeds back, and it repeats — capped at 8 turns.
